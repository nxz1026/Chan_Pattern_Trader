# CPT v0 规则决议

状态：已确认部分，未冻结全部规则。

## 1. 理论来源

- CPT 以缠论原文作为理论来源。
- `chanlun-pro`、`chanlun.py`、Pine 脚本只作为实现参考和交叉验证，不作为最终规则标准。
- 原文没有直接给出程序化细节的部分，必须在本文件中补充明确的工程解释，并标注为 CPT 实现约定。

## 2. 基础结构

- 首版采用新笔，对应参考配置：`bi_type_new`。
- 分型高低区域采用中间缠论K线：`fx_qy_middle`。
- 分型区间采用缠论K线区间：`fx_qj_ck`。
- 首版不实现线段，不把线段作为基础构件。
- 首版基础构件为走势类型。
- 走势类型内部仍需要使用分型、笔和中枢；不实现线段不等于跳过这些底层结构。

## 3. 递归映射

采用“走势类型作为下一级结构元素”的结构映射，不采用普通周期K线聚合后独立计算作为唯一递归结果。

递归链：

```text
5分钟走势类型 → 30分钟候选结构元素 → 30分钟分型 → 30分钟新笔
30分钟走势类型 → 4小时候选结构元素 → 4小时分型 → 4小时新笔
4小时走势类型 → 日线候选结构元素 → 日线分型 → 日线新笔
```

### 3.1 结构元素

每个已确认方向的低级别走势类型映射为一个高级别候选结构元素，至少保存：

- 方向；
- 起止时间；
- 起止价格；
- 整体最高价；
- 整体最低价；
- 内部中枢数量；
- 成立状态和确认时间。

### 3.2 高级别分型

高级别分型使用低级别走势类型结构元素的整体最高价、最低价识别：

- 中间结构元素最高价高于左右结构元素，作为高级别顶分型候选；
- 中间结构元素最低价低于左右结构元素，作为高级别底分型候选；
- 最终仍需满足 CPT 后续确定的分型和包含关系规则。

### 3.3 高级别新笔

- 高级别候选分型继续采用新笔规则确认；
- 首版高级别新笔至少包含 5 个低级别走势类型结构元素；
- “至少5个结构元素”是 CPT 递归实现参数，不宣称为缠论原文原句；
- 低级别走势类型重构时，对应的高级别候选结构和未确认高级别笔允许同步修正。

### 3.4 方向未定的走势类型

- 盘整走势在尚未出现明确离开方向前，不参与高级别正式计算；
- 仅作为候选结构保存；
- 出现明确向上或向下离开方向后，才转为正式结构元素。

## 4. 一买候选

首版的一买采用以下方向性定义：

1. 当前级别存在中枢结构；
2. 存在两个中枢之后继续沿原趋势方向运行的一笔，该笔称为“背驰段”；
3. 背驰段之后出现反向K线或反向结构；
4. 形成一买候选。

### 4.1 背驰段与背驰成立的区分

- 背驰段存在：结构上存在两个中枢，且第二个中枢之后存在继续沿趋势方向运行的一笔；
- 背驰成立：该笔与前面的同向段比较后，价格创新低/新高但力度减弱；
- 首版一买候选必须存在背驰段，但不强制要求背驰判定成立；
- BTC 合约的杠杆和波动特征是放宽背驰硬门槛的业务理由，不改变背驰段的结构定义。

### 4.2 预警状态

- 反向K线盘中出现：一买预警；
- 反向K线收盘后仍成立：一买候选；
- 后续形成反向新笔：一买确认候选；
- CPT 首版不自动下单，由人工决定是否交易。

“一买确认”的最终定义仍需在后续讨论中确定，包括中枢数量、反向结构强度和位置取值。

## 5. 历史与实时模式

### 5.1 历史模式

- 允许使用完整历史数据进行事后分类；
- 不要求在当时提前判断走势是否已经结束；
- 使用最终分类结果生成历史结构和评测结果；
- 必须保留结构成立时间、确认时间和重构记录，避免把事后结果伪装成实时信号。

### 5.2 实时模式

- 实时只输出预警，不输出自动交易指令；
- 未确认走势类型、高级别结构和一买允许重构或消失；
- 人工判断后再决定是否交易；
- 历史最终结果和实时当时可见结果必须分开保存。

## 6. 首版市场范围

- 首个标的：BTC；
- 合约方向：优先按 BTC USDT 本位永续合约设计；
- 交易所：Binance；
- 合约品种：Binance BTCUSDT USDT 本位永续合约；
- 首版只读公开行情，不接入下单权限。

## 7. 参考实现继承策略

CPT 不再逐项重新发明已有基础规则。凡 `chanlun-pro` 已有明确配置、对象和可验证行为的部分，首版直接采用其对应规则，并固定配置；只有与 CPT 已确认方向冲突或 `chanlun-pro` 未覆盖的部分，才单独制定 CPT 规则。

参考基线：

```text
仓库：references/chanlun-pro
提交：78ffa470
```

首版直接参考并固定：

- 缠论K线包含处理；
- 三根缠论K线分型；
- `fx_qy_middle`；
- `fx_qj_ck`；
- `bi_type_new`；
- 新笔的完成状态和端点对象；
- 笔中枢的三笔重叠基础算法；
- 中枢区间、重叠和有效状态的数据表达；
- 项目已有的背驰比较字段和一买标签语义；
- 中枢 `level` 字段；
- 中枢位置关系判断 `zs_wzgx`，用于判定同级中枢的趋势关系。

首版明确不直接采用：

- 线段、走势段及其线段中枢；
- 依赖线段的买卖点计算；
- 普通低级别K线合成高级别图表作为 CPT 递归结果；
- 项目默认的多中枢类型并行模式。

需要由 CPT 补充的内容：

- 由笔和笔中枢构造走势类型；
- 走势类型映射为高级别结构元素和新笔；
- 不强制背驰成立的一买候选；
- 历史事后分类与实时预警的双模式；
- Binance BTCUSDT USDT 本位永续数据契约。

## 8. CPT 专属规则

以下规则已经采用建议方案，作为 CPT v0 的实现约定。它们不是 `chanlun-pro` 的原样复制，也不宣称是缠论原文的逐字程序定义。

### 8.1 走势类型构成与完成分类

走势类型直接由以下结构构成：

```text
新笔序列 + 笔中枢 + 中枢之间的连接笔
```

不依赖线段和走势段。

盘整走势：

- 至少形成一个有效笔中枢；
- 后续笔仍在该中枢附近运行；
- 尚未形成两个同级、同向分离的中枢。

趋势走势：

- 至少形成两个同级笔中枢；
- 同级判断复用 `chanlun-pro` 的 `level`；
- 中枢位置和趋势关系复用 `zs_wzgx`；
- 两个中枢不构成重叠；
- 中枢位置沿同一方向移动；
- 第二中枢之后存在沿趋势方向运行的笔。

历史模式采用后验分类：完整数据处理后再确定走势类型的最终分类和边界。实时模式不提前宣称走势结束，只维护候选状态；后续反向走势类型形成并确认后，回填上一走势类型的 `closed` 事件。

走势类型状态：

```text
candidate       候选
consolidation   盘整
trend           趋势
extended        延伸
reclassified    重新分类
closed          后验关闭
```

### 8.2 一买状态

向下走势中的一买结构准备条件：

1. 当前级别存在至少两个同级中枢；
2. 第二中枢之后存在继续向下运行的一笔；
3. 该笔定义为背驰段；
4. 背驰段之后出现反向结构。

背驰段存在和背驰成立分开记录：

- 背驰段必须存在；
- 背驰是否成立不作为一买候选的硬门槛；
- 背驰比较字段和状态参考 `chanlun-pro` 保存；
- `divergence_status` 取 `not_checked`、`not_detected`、`detected`。

一买状态：

```text
structure_ready  结构准备
alert            反向K线盘中出现，实时预警
candidate        反向K线收盘后仍成立
confirmed        后续反向新笔成立
invalidated      后续结构破坏
```

CPT 只输出信号和状态，不自动下单。人工是否交易不属于结构引擎判定。

### 8.3 走势类型到高级别笔的映射

统一递归流程：

```text
低级别走势类型
→ 当前级别候选结构元素
→ 当前级别分型
→ 当前级别新笔
→ 当前级别笔中枢
→ 当前级别走势类型
```

递归链：

```text
5分钟走势类型 → 30分钟笔
30分钟走势类型 → 4小时笔
4小时走势类型 → 日线笔
```

每个结构元素至少保存：

```text
direction
start_time / end_time
start_price / end_price
high / low
center_ids
source_structure_id
status
revision
```

规则：

- 高级别分型使用低级别走势类型整体 `high`、`low`；
- 高级别新笔继续采用 `bi_type_new`；
- 首版高级别新笔至少包含 5 个低级别走势类型结构元素；
- 5 个元素是 CPT 递归工程参数，不是缠论原文规则；
- 已确认的低级别走势类型可生成高级别正式结构元素；
- 未确认的低级别走势类型只能生成高级别候选元素；
- 低级别候选变化允许同步修改高级别候选结构和未确认高级别笔；
- 正式结构不删除，变化通过 `revision` 和事件记录表达。

### 8.4 历史与实时模式

历史模式：

- 允许使用完整历史数据进行事后分类；
- 不要求在当时提前判断走势是否结束；
- 历史最终结构和实时预警分开保存；
- 必须保留首次出现、确认、失效和重构时间。

实时模式：

- 只使用当前时点已获得的数据；
- 未收盘K线只用于预警，不用于正式结构确认；
- 未确认走势、高级别结构和一买允许重构或消失；
- 预警不等于交易指令。

### 8.5 Binance 数据契约

首版范围：

```text
交易所：Binance Futures
合约：BTCUSDT
类型：USDT-M 永续
底层周期：5分钟
时区：UTC
```

数据适配器使用 Binance USDⓈ-M Futures Kline 接口：

```text
GET /fapi/v1/klines
```

参考文档：[Binance Futures Kline/Candlestick Data](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Kline-Candlestick-Data)

标准K线至少保存：

```text
open_time
open
high
low
close
volume
close_time
quote_volume
trade_count
taker_buy_base_volume
taker_buy_quote_volume
is_closed
```

规则：

- 内部时间统一为带时区 UTC；
- 正式结构只使用已收盘K线；
- 未收盘K线可以触发实时预警；
- 5分钟数据检查连续性；
- 发现缺口不自动填充，并阻止跨缺口生成正式结构；
- 30分钟、4小时、日线原生K线只作对照，不替代结构映射；
- 结构递归以5分钟数据和低级别走势类型为主输入。

### 8.6 结果与事件存储

采用“当前状态 + 不可变事件 + 信号”的三层模型。

当前结构状态至少包含：

```text
id
level
kind
direction
start_time
end_time
status
revision
first_seen_at
confirmed_at
invalidated_at
source_ids
```

`kind` 至少包括：

```text
fractal
bi
zhongshu
trend_type
signal
```

结构事件至少包括：

```text
created
updated
confirmed
reclassified
invalidated
closed
```

一买信号至少保存：

```text
signal_id
level
signal_type
status
structure_id
center_ids
divergence_status
alert_time
candidate_time
confirmed_time
invalidated_time
price
source_revision
```

事件只追加，不删除；当前状态可以更新；每次变化递增 `revision`。历史最终结果不能覆盖实时预警，实时预警不能伪装成历史确认。
