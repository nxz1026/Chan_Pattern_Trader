# CPT v0 规则决议

状态：已确认部分，未冻结全部规则。

## 1. 理论来源

- CPT 以缠论原文作为理论来源。
- 分型/笔以 `czsc`（Rust 内核，Apache-2.0）作为参考实现与交叉验证来源，不作为最终规则标准。
- 原文没有直接给出程序化细节的部分，必须在本文件中补充明确的工程解释，并标注为 CPT 实现约定。

## 2. 基础结构

- 首版采用新笔，对应参考配置：`bi_type_new`。
- 分型高低区域采用中间缠论K线：`fx_qy_middle`。
- 分型区间采用缠论K线区间：`fx_qj_ck`。
- 首版不实现线段，不把线段作为基础构件。
- 首版基础构件为走势类型。
- 走势类型内部仍需要使用分型、笔和中枢；不实现线段不等于跳过这些底层结构。

## 3. 递归映射

采用“走势类型作为下一级结构元素”的结构映射，不采用普通周期K线聚合后独立计算作为唯一递归结果。

递归链：

```text
5分钟走势类型 → 30分钟候选结构元素 → 30分钟分型 → 30分钟新笔
30分钟走势类型 → 4小时候选结构元素 → 4小时分型 → 4小时新笔
4小时走势类型 → 日线候选结构元素 → 日线分型 → 日线新笔
```

### 3.1 结构元素

每个已确认方向的低级别走势类型映射为一个高级别候选结构元素，至少保存：

- 方向；
- 起止时间；
- 起止价格；
- 整体最高价；
- 整体最低价；
- 内部中枢数量；
- 成立状态和确认时间。

### 3.2 高级别分型

高级别分型使用低级别走势类型结构元素的整体最高价、最低价识别：

- 中间结构元素最高价高于左右结构元素，作为高级别顶分型候选；
- 中间结构元素最低价低于左右结构元素，作为高级别底分型候选；
- 最终仍需满足 CPT 后续确定的分型和包含关系规则。

### 3.3 高级别新笔

- 高级别候选分型继续采用新笔规则确认；
- 首版高级别新笔至少包含 5 个低级别走势类型结构元素；
- “至少5个结构元素”是 CPT 递归实现参数，不宣称为缠论原文原句；
- 低级别走势类型重构时，对应的高级别候选结构和未确认高级别笔允许同步修正。

### 3.4 方向未定的走势类型

- 盘整走势在尚未出现明确离开方向前，不参与高级别正式计算；
- 仅作为候选结构保存；
- 出现明确向上或向下离开方向后，才转为正式结构元素。

## 4. 一买候选

首版的一买采用以下方向性定义：

1. 当前级别存在中枢结构；
2. 存在两个中枢之后继续沿原趋势方向运行的一笔，该笔称为“背驰段”；
3. 背驰段之后出现反向K线或反向结构；
4. 形成一买候选。

### 4.1 背驰段与背驰成立的区分

- 背驰段存在：结构上存在两个中枢，且第二个中枢之后存在继续沿趋势方向运行的一笔；
- 背驰成立：该笔与前面的同向段比较后，价格创新低/新高但力度减弱；
- 首版一买候选必须存在背驰段，但不强制要求背驰判定成立；
- BTC 合约的杠杆和波动特征是放宽背驰硬门槛的业务理由，不改变背驰段的结构定义。

### 4.2 预警状态

- 反向K线盘中出现：一买预警；
- 反向K线收盘后仍成立：一买候选；
- 后续形成反向新笔：一买确认候选；
- CPT 首版不自动下单，由人工决定是否交易。

“一买确认”的最终定义仍需在后续讨论中确定，包括中枢数量、反向结构强度和位置取值。

## 5. 历史与实时模式

### 5.1 历史模式

- 允许使用完整历史数据进行事后分类；
- 不要求在当时提前判断走势是否已经结束；
- 使用最终分类结果生成历史结构和评测结果；
- 必须保留结构成立时间、确认时间和重构记录，避免把事后结果伪装成实时信号。

### 5.2 实时模式

- 实时只输出预警，不输出自动交易指令；
- 未确认走势类型、高级别结构和一买允许重构或消失；
- 人工判断后再决定是否交易；
- 历史最终结果和实时当时可见结果必须分开保存。

## 6. 首版市场范围

- 首个标的：BTC；
- 合约方向：优先按 BTC USDT 本位永续合约设计；
- 交易所：Binance；
- 合约品种：Binance BTCUSDT USDT 本位永续合约；
- 首版只读公开行情，不接入下单权限。

## 7. 参考实现继承策略

参考基线（2026-09-24 起）：

```text
分型 / 笔 / 一买一卖谓词：
    references/czsc@701e480a545004f945bb1721e510ae610ad90c4c（Apache-2.0）
    通过可选依赖 extra `chan = ["czsc==1.0.1"]` 接入
中枢 / 走势类型 / 线段 / 递归：
    CPT 自研（czsc 不提供这些能力）
```

CPT 不再逐项重新发明已有基础规则。凡 czsc 已有明确实现、可验证行为的部分，首版直接采用其规则并固定配置；只有与 CPT 已确认方向冲突、或 czsc 未覆盖的部分，才单独制定 CPT 规则。

### 7.1 直接采用 czsc

- 缠论K线包含处理；
- 三根缠论K线分型；
- 新笔判定与笔的完成状态、端点对象；
- 笔的力度度量：`power_price` / `power_volume` / `length`；
- 一买/一卖结构谓词（见 §7.3）。

固定配置：`min_bi_len = 6`，量纲＝去包含后的K线根数（见 §9.8）。

### 7.2 CPT 自研（czsc 不提供，或不宜采用）

| 环节 | 决定 | 依据 |
|---|---|---|
| 中枢 | **CPT 自研** | czsc 的中枢会产出 <3 笔的假中枢，且无笔级溯源；CPT 要求严格三笔重叠 + 至少 3 笔 |
| 走势类型 | CPT 自研 | czsc 无此概念 |
| 线段 / 走势段 | CPT 自研 | czsc 无线段中枢 |
| 递归（走势类型 → 高级别笔） | CPT 自研 | czsc 无此能力 |

中枢延伸口径（2026-09-24 修正）：**区间由建枢前三笔唯一确定，延伸只延长中枢、不收缩区间**，详见 §9.9。

### 7.3 一买/一卖的归属

czsc 的一买/一卖判定是纯结构谓词。CPT 逐行移植到 `cpt/domain/first_buy.py`，而不直接调用——czsc 的 Python 绑定把它包在信号模板体系里（需要分析器对象、模板名与参数字典），而 CPT 需要的是"输入一串笔、输出布尔值"的纯谓词。

移植后与 czsc 在 3 个真实 fixture 上逐笔数交叉验证一致（6/6，含正例）。

与 `cpt/domain/signal.py` 的分工：`signal.py` 是**状态机**，消费结构事实并管理状态阶梯；`first_buy.py` 负责**算出**那个最关键的事实——"这一段走势是否构成一买"。

### 7.4 明确不采用

- 线段、走势段及其线段中枢；
- 依赖线段的买卖点计算；
- 普通低级别K线合成高级别图表作为 CPT 递归结果；
- czsc 的多中枢类型并行模式与信号模板体系（CPT 只取其结构算法）。

### 7.5 需要由 CPT 补充的内容

- 由笔和笔中枢构造走势类型；
- 走势类型映射为高级别结构元素和新笔；
- 不强制背驰成立的一买候选；
- 历史事后分类与实时预警的双模式；
- Binance BTCUSDT USDT 本位永续数据契约。

### 7.6 已移除的参照（2026-09-24，G1 决议）

`chanlun-pro`（提交 `78ffa470`）已移除。其分型/笔实现与缠论定义冲突：笔端点中位跨度仅 **2 根**原始K线，**66–74%** 的笔跨度不足 4 根，两根 3K 分型窗口重叠——定义上不可能成笔。对照 czsc 的 **9–10 根**中位跨度与 **4–6%** 短跨度占比，差距是定义级的，不是参数级的。相关的 `references/chanlun-pro` 路径、`78ffa470` 提交号与 `oracle-parity` CI 作业均已一并删除。

## 8. CPT 专属规则

以下规则已经采用建议方案，作为 CPT v0 的实现约定。它们不是任何参考仓库的原样复制，也不宣称是缠论原文的逐字程序定义。

### 8.1 走势类型构成与完成分类

走势类型直接由以下结构构成：

```text
新笔序列 + 笔中枢 + 中枢之间的连接笔
```

不依赖线段和走势段。

盘整走势：

- 至少形成一个有效笔中枢；
- 后续笔仍在该中枢附近运行；
- 尚未形成两个同级、同向分离的中枢。

趋势走势：

- 至少形成两个同级笔中枢；
- 同级判断复用笔的 `level` 字段；
- 中枢位置和趋势关系复用 `zs_wzgx`；
- 两个中枢不构成重叠；
- 中枢位置沿同一方向移动；
- 第二中枢之后存在沿趋势方向运行的笔。

历史模式采用后验分类：完整数据处理后再确定走势类型的最终分类和边界。实时模式不提前宣称走势结束，只维护候选状态；后续反向走势类型形成并确认后，回填上一走势类型的 `closed` 事件。

走势类型状态：

```text
forming         形成中（原 candidate，见 §9.4 改名）
consolidation   盘整
trend           趋势
extended        延伸
reclassified    重新分类
closed          后验关闭
open_end        开放终态（见 §9.3）
```

### 8.2 一买状态

向下走势中的一买结构准备条件：

1. 当前级别存在至少两个同级中枢；
2. 第二中枢之后存在继续向下运行的一笔；
3. 该笔定义为背驰段；
4. 背驰段之后出现反向结构。

背驰段存在和背驰成立分开记录：

- 背驰段必须存在；
- 背驰是否成立不作为一买候选的硬门槛；
- 背驰比较字段和状态按 `docs/rules.md` §9.6 保存；
- `divergence_status` 取 `not_checked`、`not_detected`、`detected`。

一买状态：

```text
structure_ready  结构准备
alert            反向K线盘中出现，实时预警
candidate        反向K线收盘后仍成立
confirmed        后续反向新笔成立
invalidated      后续结构破坏
```

CPT 只输出信号和状态，不自动下单。人工是否交易不属于结构引擎判定。

### 8.3 走势类型到高级别笔的映射

统一递归流程：

```text
低级别走势类型
→ 当前级别候选结构元素
→ 当前级别分型
→ 当前级别新笔
→ 当前级别笔中枢
→ 当前级别走势类型
```

递归链：

```text
5分钟走势类型 → 30分钟笔
30分钟走势类型 → 4小时笔
4小时走势类型 → 日线笔
```

每个结构元素至少保存：

```text
direction
start_time / end_time
start_price / end_price
high / low
center_ids
source_structure_id
status
revision
```

规则：

- 高级别分型使用低级别走势类型整体 `high`、`low`；
- 高级别新笔继续采用 `bi_type_new`；
- 首版高级别新笔至少包含 5 个低级别走势类型结构元素；
- 5 个元素是 CPT 递归工程参数，不是缠论原文规则；
- 已确认的低级别走势类型可生成高级别正式结构元素；
- 未确认的低级别走势类型只能生成高级别候选元素；
- 低级别候选变化允许同步修改高级别候选结构和未确认高级别笔；
- 正式结构不删除，变化通过 `revision` 和事件记录表达。

### 8.4 历史与实时模式

历史模式：

- 允许使用完整历史数据进行事后分类；
- 不要求在当时提前判断走势是否结束；
- 历史最终结构和实时预警分开保存；
- 必须保留首次出现、确认、失效和重构时间。

实时模式：

- 只使用当前时点已获得的数据；
- 未收盘K线只用于预警，不用于正式结构确认；
- 未确认走势、高级别结构和一买允许重构或消失；
- 预警不等于交易指令。

### 8.5 Binance 数据契约

首版范围：

```text
交易所：Binance Futures
合约：BTCUSDT
类型：USDT-M 永续
底层周期：5分钟
时区：UTC
```

数据适配器使用 Binance USDⓈ-M Futures Kline 接口：

```text
GET /fapi/v1/klines
```

参考文档：[Binance Futures Kline/Candlestick Data](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Kline-Candlestick-Data)

标准K线至少保存：

```text
open_time
open
high
low
close
volume
close_time
quote_volume
trade_count
taker_buy_base_volume
taker_buy_quote_volume
is_closed
```

规则：

- 内部时间统一为带时区 UTC；
- 正式结构只使用已收盘K线；
- 未收盘K线可以触发实时预警；
- 5分钟数据检查连续性；
- 发现缺口不自动填充，并阻止跨缺口生成正式结构；
- 30分钟、4小时、日线原生K线只作对照，不替代结构映射；
- 结构递归以5分钟数据和低级别走势类型为主输入。

### 8.6 结果与事件存储

采用“当前状态 + 不可变事件 + 信号”的三层模型。

当前结构状态至少包含：

```text
id
level
kind
direction
start_time
end_time
status
revision
first_seen_at
confirmed_at
invalidated_at
source_ids
```

`kind` 至少包括：

```text
fractal
bi
zhongshu
trend_type
signal
```

结构事件至少包括：

```text
created
updated
confirmed
reclassified
invalidated
closed
```

一买信号至少保存：

```text
signal_id
level
signal_type
status
structure_id
center_ids
divergence_status
alert_time
candidate_time
confirmed_time
invalidated_time
price
source_revision
```

事件只追加，不删除；当前状态可以更新；每次变化递增 `revision`。历史最终结果不能覆盖实时预警，实时预警不能伪装成历史确认。

## 9. 已冻结约定（v0，2026-09-22）

以下条目原为未冻结缝隙，现已冻结，与 `docs/architecture.md` §8 一致。

### 9.1 高级别分型包含关系

- 高级别（结构元素层）不做包含合并，只做过滤。
- 结构元素由完整走势类型构成、时间相邻不重叠；包含合并既无缠论原文依据，又会破坏 `source_structure_id` 追溯链。

### 9.2 级联重构规则

- 确认即冻结，重构走新事件。
- 候选结构就地更新（`revision+1`）；已确认结构绝不原地修改，失效即发 `invalidated` 事件。
- 高层结构记录 `source_structure_id + source_revision`；低级别 `revision` 变化时，扫描依赖滞后的高层结构并标记。这是"无未来函数"的执行机制。

### 9.3 走势类型开放终态

- 增加显式终态 `open_end`，与 `closed_by_reversal`（由后续反向走势类型回填关闭）区分。
- 历史模式数据边界截断时，最后一个走势类型标记为 `open_end`；`open_end` 不参与一买完成统计。
- 实时模式无需特殊处理。

### 9.4 术语：走势类型状态改名

- 走势类型状态 `candidate` 改名 `forming`，避免与一买信号状态 `candidate` 冲突。
- 事件类型统一为 `created / updated / confirmed / reclassified / invalidated / closed`。

### 9.5 中枢位置关系档位

- 首版固定 `zs_wzgx = zgd`（高点比 zg、低点比 zd），写入 `RulesConfig`，不按市场分别配置。

### 9.6 背驰力度口径

- 复用 MACD 柱面积法，参数固定 `(12,26,9)`。
- `divergence_status ∈ {not_checked, not_detected, detected}`。

### 9.7 "至少5个结构元素"的语义

- "高级别新笔至少包含 5 个低级别走势类型结构元素"是 CPT 递归工程参数，量纲为**低级别结构元素数**，与 §9.8 的 `min_bi_len` 不同，**不可混用**。
- 必须用人工构造案例验证该参数下高级别笔的行为。

### 9.8 底层笔最少跨度 `min_bi_len`（2026-09-24 新增，R14）

- 字段：`RulesConfig.min_bi_len`，默认 **6**，量纲为**去包含后的 K 线根数**。
- 与 §9.7 的 `min_elements_for_higher_bi` 量纲不同，两者独立存在，不可互相替代。
- 取值依据：与 czsc `check_bi` 的门槛对齐（`crates/czsc-core/src/analyze/utils.rs`，条件为
  `!ab_include && bars_a.len() >= min_bi_len`）。实测在 4–7 区间笔数几乎不敏感
  （3 个 oracle fixture 恒 ~50 笔），8 起急降，故直接采用 czsc 上游默认 6，不自造数值。
- 注意 `ab_include` 分支：当两端分型 K 线互相包含时该门槛**不适用**，因此会存在少量
  跨度小于 `min_bi_len` 的笔（实测占比 4–6%），这是既定规则而非缺陷。

### 9.9 中枢区间与延伸口径（2026-09-24 修正，R14）

- **建枢**：连续三笔方向两两相反，且三者价格区间存在共同重叠；重叠区间取
  `zg = min(三笔 high)`、`zd = max(三笔 low)`，并要求**严格** `zg > zd`
  （只在单点接触不算中枢）。
- **延伸不收缩区间**：后续笔与中枢区间重叠（闭区间，`bi.high >= zd` 且
  `bi.low <= zg`）时纳入该笔——`end_time` 后移、`bi_ids` 追加，但
  **`zg` / `zd` 保持不变**。中枢区间由建枢前三笔唯一确定。
- **依据**：缠论原文的中枢区间＝连续三段走势类型的**共同重叠部分**；延伸只延长
  中枢、不收缩区间。2026-09-24 之前的实现把区间单调收缩（`zg = min(...)` /
  `zd = max(...)`），会把一个中枢切成多个窄区间并产出宽度趋零的畸形中枢
  （实测最小宽度 **4.5**，修正后为 **17.2**）。
- **笔不跨中枢复用**：延伸结束后从"未能进入本中枢的那一笔"起重新扫描新窗口。
  §8.1 的趋势判定以"两个中枢不构成重叠"为前提，允许复用笔会产出时间区间重叠
  甚至嵌套的中枢，破坏该前提并重复计入同一笔。
- **交叉验证**：修正后 CPT 中枢的区间宽与纳入笔数在 3 个真实 fixture 上与 czsc
  一致（含 fixture1 的 `[151.0, 66.5, 17.2]` / `[38, 6, 5]` 逐项相同）。
