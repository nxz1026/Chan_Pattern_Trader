### 三个「声明 vs 实际」的坑，值得你知道

1. **候选集**（R42）：`priority_codes` 原本是 `watchlist ∪ hot_pool ∪ {source IS NOT NULL}`，
   也就是**已经有真值的那 2197 只** —— 而「58% 是占位值」正是重算要解决的主问题，
   却一只都碰不到。已加 `--scope`（默认 `placeholder`）。
2. **巡检**（R43）：R38 按要求建了 `run_inspection.py` 并真发过飞书，但它**从未被调度**。
   装了 cron 后又发现**发了也发不出** —— webhook 只在 systemd 的 `EnvironmentFile` 里，
   cron 没有等价物。两处都已修。
3. **台阶 off-by-one**（R40）：`factor_from_actions` 从最新除权往前连乘，
   `fmap[s] = Π{ex >= s}`，而一根 bar 要的是 `Π{ex <= d}`，原代码取了 `Π{ex > d}`
   —— **正好取反**。后果不是精度问题而是**方向**问题：除权日价格已跌、因子还停在
   除权前的水平，后复权价在除权日凭空多出一次下跌（实测 -65.7%）。
   修法：`f(d) = 1 / fmap[min{ex > d}]`。

### 3.1 生产因子表 `asel.ref_adjust_factor` 是**坏的**

| 分桶 | 只数 | 含义 |
|---|---|---|
| `source IS NULL` | **3036** | 占位，从未算过（其中 3028 只恰好恒为 1.0） |

**2197 只「有真值」的票里 96.7% 非单调。** 纯后复权因子必须单调不降（除权日向上跳
把分红加回去），所以那一列对 2125 只**不是后复权因子**。

后果很具体：占位票 `hfq_factor ≡ 1.0` ⇒ 后复权价 == 不复权价 ⇒ 每个除权日的
价格跳空被当成**真实下跌**喂给缠论 ⇒ **58% 的 A 股宇宙在用未复权价算结构**。

### 3.2 暂存表 `asel.ref_adjust_factor_v2` 已算完 2169 只

- 成功 **2169** / 失败 **28**
- 28 只失败原因**只有一个**：除权日早于本地 bar 起点（`2024-01-02`，最早的到
  2000-05-23），取不到「除权前收盘」。代码在这种情况下**整只拒写**而不是写个偏小的值
  —— 这是**正确**的行为（跳过早期台阶会让整段因子系统性偏小）。这 28 只在暂存表里
  没有行，切表不会碰到它们。

## 4. ⚠️ 未修的 bug：东财「返回数据为空」会掐停整轮

**现象**：`--scope placeholder` 那轮在 2026-10-02 13:50 启动后 3 分钟就死了。

```
上次因 EastmoneyActionError 提前停止
  detail: 东财分红接口返回失败（001239）：返回数据为空
```

**已确认不是限流**：001239 / 001240 连查 3 次都返回同样的 `success:false,
message:"返回数据为空"`，而同一批的 001238 正常返回 3 条。**这是确定性的 ——
这些票在东财那张表里确实没有分红记录。**

**根因在错误分类**（`cpt/adapters/eastmoney_actions.py`）：

```python
if payload.get("success") is False:
    raise EastmoneyActionError(...)     # ← 被 _EastmoneySource 归为 fatal
```

而 `_EastmoneySource.fatal_errors = (EastmoneyActionError,)`，fatal 会让
`process_code` 直接抛出、`main` 立即停整轮。**于是一只「从没分过红的票」
把整轮 3000 只的任务掐死了。**

**修法**（未做）：把「`success:false` + 空数据」与「响应格式坏」区分开 ——
前者应返回**空行动列表**（合法结果：这家公司没分过红），只有非 JSON / 结构损坏
才是 fatal。注意别重复 R40 的教训：**新增异常类型时注意 `except` 的顺序**，
子类会被父类分支先吃掉。

**这个 bug 修好之前，不要挂任何无人值守的定时重算。**

## 7. Windows 开发机的坑（血泪，已咬多次）

- **内联 Python 会被 PowerShell 吞**。`ssh oracle "... python -c "...""` 里的
  中文/引号/`$(...)`/`$f` 都会被本地先算掉。**复杂命令一律：写脚本文件 → `scp`
  → 远端 `tr -d '
'` 归一化 → `bash` 执行。**
- **CRLF**：从 Windows `scp` 上去的文件带 `
`，仓/服务器规范是 LF。部署前必须
  `tr -d '
'` 归一化，否则线上与仓不一致。
- **GBK 显示**：控制台按 GBK 解码 UTF-8，中文变乱码、且**行尾会被吃掉**
  （`�?` 那种显示不代表文件坏了）。设 `$env:PYTHONIOENCODING='utf-8'`。
- **远端 `git clean` 不带 `-x`**：`-x` 会把 gitignore 挡住的
  `deploy/env/cpt-dashboard.env`（唯一存飞书 webhook 的地方）一起删掉。
  清理前先 `tar` 备份并核对文件数。
- **测试基线**（`--junit-xml` 取值）：**853 tests / 15 failures / 1 error /
  29 skipped / 808 passed**。15 条全是既存环境基线（14 条 `fcntl` Windows 不可导入
  + 2 条无浏览器 chromium）。判断「有没有打破契约」要 `git stash` 后跑一遍
  **逐条对比失败名单**，**不要数条数**。

## 8. 工作纪律（这个项目一贯的做法，别跳过）

1. **先量结构，再真机验，最后才动代码。** 每个怀疑都要用真机验证。
2. **不看因子值，看可观测后果。** 台阶倍数对了不代表挂的日子对（R40）；
   送转的「列名直觉」错了不代表数据错（R41）。判决要用**独立判据** ——
   「后复权价在除权日是否连续」、「除权后实际收盘价落在哪一方」。
3. **独立判据第一次给出与预期相反的答案时，先怀疑自己的实现。**（R41 差点把自己
   的 bug 写成「东财源不可靠」。）
4. **改完要复验，且用同一个判据对比修复前后。**
5. **生产因子表一行都没动过** —— 保持这个状态，直到有人明确决定切换。
