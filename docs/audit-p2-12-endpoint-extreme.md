## 1. 缺陷本体

报告 §4 P2-12 原文：`cpt/domain/bi.py:192` + `:94-95` —— `end_idx += 2` 跳过同类
分型，而 `_make_bi` 的 `high/low` 只取两端点 ⇒ 区间内更极端的同类分型被永久丢弃；
`zhongshu._overlap` 直接用该 `high/low`。

**报告说对了一半，量出来比它说的更严重。** 准确的不变量是：

| | 含义 |
|---|---|
| **I2** | 笔窗口 `[s, e]` 内与**起点**同类的分型里，起点最极端 |
| **I3** | 笔窗口 `[s, e]` 内与**终点**同类的分型里，终点最极端 |
| **I4** | 相邻笔共享端点（连续）；每笔两端异类 |

「更极端」= 顶取更高 `high`、底取更低 `low`（`_is_more_extreme`，严格不等）。

**关键对照——缺陷完全由门槛路径引入：**

| gate | 笔 | 中枢 | I2 违规 | I3 违规 | 连续 | 异类 |
|---|---|---|---|---|---|---|
| `None` | 326 | 33 | **0** | **0** | ✓ | ✓ |
| 6 | 98 | 21 | **53** | **49** | ✓ | ✓ |

`gate=None` 时零违规是**结构性**的：`bi.py:144-146` 的前置折叠
（`if fractal.kind == current.kind: if _is_more_extreme(...)`）只在**输入相邻**的
同类分型间比较；一旦 `anchors` 严格交替，两个同类端点之间必然隔着一个异类端点，
再也不会被比较。`end_idx += 2` 让它们**重新相邻**，却不重新裁定 ⇒ 违规。

三个 fixture、gate=6 的全量：

| fixture | 笔 | 中枢 | I2 | I3 | DP 上界 |
|---|---|---|---|---|---|
| `btcusdt_5m_2024-02-01` | 98 | 21 | 53 | 49 | **41** |
| `btcusdt_5m_2024-09-01` | 104 | 21 | 57 | 52 | **53** |
| `btcusdt_5m_2025-04-01` | 110 | 19 | 59 | 57 | **38** |

## 2. 参照实现（czsc）满足这个不变量

`czsc.CZSC(raw, max_bi_num=MAX_BI_NUM_UNLIMITED, min_bi_len=6)`，用它的 `fx_list` 作分型集合：

| fixture | czsc 笔 | I2 违规 | I3 违规 | 连续 | 异类 |
|---|---|---|---|---|---|
| `btcusdt_5m_2024-02-01` | 88 | 0 | 0 | ✓ | ✓ |
| `btcusdt_5m_2024-09-01` | 90 | 3 | 0 | ✓ | ✓ |
| `btcusdt_5m_2025-04-01` | 74 | 2 | 0 | ✓ | ✓ |

所以 I2/I3 不是我们凭空加的标准，**它就是参照口径**。

⚠️ R68 口径更新：上表原用 `max_bi_num=0`（笔数 50/49/49、违规 0/1/2）。那个 0 会被
内核当「未指定」回落默认 50，把笔数砍掉近半（见下节）。放开后笔数 88/90/74、
违规 0/3/2 —— **结论不变**（I2/I3 基本满足，I3 恒为 0），只是样本更完整。
数据源已重跑：`docs/audit-p2-12-evidence.json`。

⚠️ 但 czsc 侧有 1 笔无法映射到 `fx_list`（笔端点是「已失效但被记住的分型」），
量测时如实标出。

### 但不是「一个文件的差距」

| fixture | native 分型 | czsc 分型（`max_bi_num=0`） | 差 |
|---|---|---|---|
| `btcusdt_5m_2024-02-01` | 327 | 202 | +125 |
| `btcusdt_5m_2024-09-01` | 357 | 203 | +154 |

⚠️ **R68 更正（2026-10-19）：上表这一列的「差」是量测伪影，不是算法差异。**

「czsc 分型」用的是 `max_bi_num=0`。实测（czsc 1.0.1）那个 0 **不是「不限笔数」**，
而是落进内核的「未指定」分支、取默认值 **50**：

```rust
// crates/czsc-core/src/analyze/mod.rs:88
pub fn resolve_max_bi_num(explicit: usize) -> usize {
    resolve_env_usize(explicit, "CZSC_MAX_BI_NUM", "czsc_max_bi_num", 50)
}
// :65 —— 第一条就是 if explicit > 0；0 走不到这里
fn resolve_env_usize(explicit: usize, upper: &str, lower: &str, default: usize) -> usize {
    if explicit > 0 { return explicit; }
    ...
    default
}
```

截断发生在 `:229`（`bi_list.drain(0..start_idx)`），**`bars_raw` 也跟着从头 drain**
（`:243` 用 `bi_list.first().fx_a.elements[0].dt` 反推），所以**分型集合也被截掉**：
1000 根 fixture 下 `bars_raw` 1000 → 593、`fx_list` 322 → 202。

把 `max_bi_num` 真正放开后重测：

| fixture | native 分型 | czsc 分型（`max_bi_num=1e9`） | 共同窗口内序列是否相同 |
|---|---|---|---|
| `btcusdt_5m_2024-02-01` | 327 | 322 | **下标与种类完全相同** |
| `btcusdt_5m_2024-09-01` | 357 | 356 | **下标与种类完全相同** |
| `btcusdt_5m_2025-04-01` | 353 | 348 | **下标与种类完全相同** |

native 多出的 1~5 个分型全在 czsc 因截断而**没覆盖到的窗口边缘**，不是「上游分型
检测差异」。**两套分型检测在共同窗口内是同一个东西。**

⇒ 下面这句原结论**作废**：「native 的分型集合本身就比 czsc 大 50%~75%…
上游分型检测（是否做分型级别过滤/包含处理）差异更大」。分型层**不存在**待对齐的差异。

## 3. 为什么「采纳报告建议 + 升 v2」不可行

### 3.1 两个约束冲突（DP 证明，非推测）

在 native 自己的分型集上，对「端点=I2+I3 合法 且 跨度 ≥ gate」的全部合法端点对做
**穷举 DP**，求最长合法端点链 —— 这是**任何**算法都超不过的上界：

| gate | `2024-02-01` | `2024-09-01` | `2025-04-01` |
|---|---|---|---|
| 3 | 132 | 123 | 137 |
| 4 | 89 | 89 | 70 |
| 5 | 57 | 61 | 60 |
| **6（现行）** | **41** | **53** | **38** |
| 7 | 33 | 41 | 32 |
| 8 | 32 | 35 | 30 |
| 10 | 26 | 21 | 22 |

⇒ 在现行 gate=6 下，满足不变量的笔数**最多** 41/53/38，即比现行 98/104/110
**少 58%/49%/65%**。这不是我的实现不够好，是约束本身的代价。

（另有独立佐证：8 锚点 × 5 种 gate 的随机穷举中，**32.9%（657/2000）的输入
双约束无解**。）

### 3.2 报告建议的两个修法都失败

用真 `build_bis` 输出交叉核对（`cur()` 复现笔数与真实现逐 fixture 一致）：

| 变体 | 笔 | 中枢 | I2 | I3 | 中枢最小宽 |
|---|---|---|---|---|---|
| 现行 | 98/104/110 | 21/21/19 | 53/57/59 | 49/52/57 | 2.9/9.0/83.0 |
| **报告建议①** | 96/102/106 | 16/18/19 | **38/49/54** | 41/48/54 | 7.2/9.0/13.5 |
| **报告建议②** | 98/104/110 | **5**/21/13 | 53/57/59 | 49/52/57 | 61.9/6.4/88.0 |
| DP 最优 | **41/53/38** | 4/7/6 | **0** | **0** | 60.3/69.1/281.4 |

- **建议①**（"若更极端则把 `start_idx` 前移到 `end_idx-1`"）：只把违规从
  53/57/59 降到 38/49/54，**一个也没归零**；并且 `start_idx` 前移会让笔与笔之间
  出现空洞，违反 `bi.py:127` 与 `docs/rules.md:529`/`:584` 明确承诺的「合并端点、
  不丢弃」语义。
- **建议②**（"high/low 取区间极值"）：**端点完全不动**，所以 I2/I3 一个都不修
  （53/57/59 原样）；它只把 `Bi.high/low` 加宽，而加宽会**缩小**三笔重叠区，
  把 `2024-02-01` 的中枢从 21 个压成 5 个 —— 且这 5 个的最小宽度 61.9
  是「变大」而非退化，风险与收益都不对。

> 报告没提的第三条路（DP）确实能归零，但代价见 3.1。

### 3.3 与「合并端点」语义冲突

`cpt/domain/bi.py:127` 的契约是：*跨度不足时**合并端点**而不是丢弃该笔；合并的含义是
「当前笔的终点顺延到下一个够远的异类端点」*。

DP 最优解**不是**贪心合并 —— 它是全局选择，会主动**跳过**某些合法端点以换取更长的链。
落地等于把「局部合并」改成「全局 DP 选择」，这是**改语义**，不只是修 bug。

### 3.4 一旦落地，波及面

- `SCHEMA_VERSION` v1 → v2（`cpt/domain/config.py:58` 定义；`cpt/domain/config.py:214` 版本不符即抛错）
- 全部回放 fixture 重建（笔/中枢/信号/背驰全变）
- `min_bi_len` 重新校准：现行 6 是为「无约束贪心」调的；DP 解在 gate=4 时笔数
  89/89/70、gate=5 时 57/61/60，需整套重扫并同步
  `docs/calibration-r56-min-bi-len.json`
- `min_bi_len_by_interval` 各档（`cpt/domain/config.py`）全部重调
- 历史结构/信号**不可比**

## 4. 判据自身的两个坑（后续量测务必避开）

这两条都**实际坑过**本项目多轮量测，制造过互相矛盾的数字：

1. **端点映射必须 start↔start、end↔end。**
   `Bi.start_time` = 起点分型的 `start_time`，但 `Bi.end_time` = 终点分型的
   **`end_time`**（`_make_bi`：`start_time=start.start_time, end_time=end.end_time`）。
   用 `f.start_time == b.end_time` 找终点**恒不匹配**，末端检查被**静默跳过** ——
   早期报出的「末违规 47/52/57」和「53/57/59（末违规 0）」两套数字都是这么来的。

2. **跨度必须按 `merged_index` 差算，不是分型列表下标差。**
   门槛的量纲是**去包含后** K 线根数（`Fractal` docstring 明确「别拿 `bar_index`
   当笔的跨度」）。分型在合并序列里**稀疏**，两种量纲实测能差一倍：
   `2024-02-01` gate=5 时，用下标差得 DP 上界 25，用 `merged_index` 差得 **57**。
   用错会把约束的代价低估一半以上。

3. **czsc `FX` 的属性陷阱**：`FX.mark` 才是分型种类（`Mark` 枚举，`str()` 为
   「顶分型」/「底分型」）；`FX.fx` **不是**种类，是**价格字符串**（59 种取值）。
   曾用 `str(mark).endswith("G")` 判断导致全部被判成底，产出「连续 4 个同类分型」
   的假象，据此得出的结论全部作废。
   另：`FX` **没有** `.id`，笔端点用 `bi.fx_a.dt` / `bi.fx_b.dt`。

- ~~上游还有更大的**既有**分型集差异（327 vs 202）未解决，先修 `bi.py` 是在错的地基上施工。~~
